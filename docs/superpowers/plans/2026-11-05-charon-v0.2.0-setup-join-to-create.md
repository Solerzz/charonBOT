# Charon v0.2.0 Setup and Join-to-Create Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a private administrative setup dashboard and a persistent join-to-create voice-room lifecycle with the approved Minimalist Monochrome call panel.

**Architecture:** Extend the feature-first modular monolith with independent `setup` and `calls` modules. Services own rules behind repository and Discord gateway ports; Prisma and Discord.js stay in adapters composed explicitly from `application.ts`.

**Tech Stack:** Node.js 20.19+, TypeScript strict, Discord.js 14.28.1, Prisma 7.10.1 with PostgreSQL, Zod 4.6.7, Pino 10.4.0, Vitest 5.1.0.

**Spec:** `docs/superpowers/specs/2026-11-05-charon-v0.2.0-setup-join-to-create-design.md`

## Global Constraints

- Preserve the existing explicit `InteractionRegistry` and dependency-composition pattern.
- PostgreSQL is the source of truth; Discord IDs are strings separate from internal UUIDs.
- `/setup init` is guild-only, permission-checked server-side, and always ephemeral.
- Voice Creators are identified only by persisted Discord channel ID.
- Initial room names use activity then display-name fallback and are Unicode-safely limited to 11 characters.
- The `v0.2.0` call panel follows Minimalist Monochrome and every future control is disabled.
- No ownership claims, moderation, reputation, startup reconciliation, Redis, microservices, or web dashboard.
- Validate external interaction data with Zod and never log tokens, message content, or user-provided names.

## Review Focus

- Duplicate or concurrent voice-state events for one member must create exactly one room; Task 6 pins this with concurrent calls.
- A member who already owns an active room must be moved to it instead of receiving another; Task 6 tests this branch.
- Discord or database failures after channel creation must not leave an orphaned active room; Task 6 tests each compensation boundary.
- Forged component IDs or stale/deleted Discord channels must produce safe ephemeral responses without mutation; Task 4 tests both.
- Deleting a Voice Creator while it has active rooms must block only new creation and allow existing rooms to close normally; Tasks 2 and 6 test both halves.

## File Structure

### Persistence and shared utilities

- `prisma/schema.prisma` — `VoiceCreator`, `TemporaryRoom`, and state enums.
- `prisma/migrations/20261105000000_v0_2_setup_join_to_create/migration.sql` — database migration.
- `src/generated/prisma/**` — generated Prisma 7 client; never edit manually.
- `src/shared/keyed-mutex.ts` — serializes creation work by guild/member key.

### Setup module

- `src/modules/setup/setup.schemas.ts` — Zod schemas for IDs, component payloads, and modal values.
- `src/modules/setup/setup.repository.ts` — setup persistence port and Prisma adapter.
- `src/modules/setup/setup.service.ts` — authorization-independent setup rules.
- `src/modules/setup/setup.discord.ts` — Discord guild adapter for channel lookup and rename.
- `src/modules/setup/setup.views.ts` — Minimalist Monochrome ephemeral dashboard builders.
- `src/modules/setup/setup.command.ts` — `/setup init` definition and command handler.
- `src/modules/setup/setup.interactions.ts` — buttons, selects, modal submissions, and permission revalidation.

### Calls module

- `src/modules/calls/call.schemas.ts` — room-name, voice-transition, and Discord-ID validation.
- `src/modules/calls/call.repository.ts` — temporary-room persistence port and Prisma adapter.
- `src/modules/calls/call.discord.ts` — channel create/move/message/delete gateway scoped to a voice event.
- `src/modules/calls/call-panel.view.ts` — disabled Minimalist Monochrome control panel.
- `src/modules/calls/call.service.ts` — creation, compensation, owner departure, and closure workflow.
- `src/modules/calls/voice-state.handler.ts` — Discord `VoiceState` to domain transition adapter.

### Composition, registration, and documentation

- `src/application.ts` — register setup interactions and voice-state dispatcher.
- `scripts/register-commands.ts` — publish `/setup` alongside `/status`.
- `docs/architecture.md`, `CHANGELOG.md`, `docs/releases/v0.2.0.md`, `package.json` — release documentation and version.
